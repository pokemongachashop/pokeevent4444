# 포켓몬 숨바꼭질 3D

Three.js 3D 실시간 멀티플레이 숨바꼭질(프롭 헌트) 웹게임입니다. 한 방 최대 20명, PC·모바일 브라우저 지원.
숨는 팀은 맵의 사물로 변신하고, 술래는 **직접 조준하고 포획 버튼을 눌러야만** 잡을 수 있습니다.

**Firebase Spark(무료) 요금제 전용**입니다. Cloud Functions 나 별도 서버를 쓰지 않으며, 요금제 변경이 필요 없습니다.
게임 규칙의 검사는 Realtime Database **보안 규칙**이 서버 쪽에서 수행합니다.

> 비공식 팬 게임입니다. 공식 포켓몬 모델·이미지·음악은 포함하지 않으며, 캐릭터와 사물은 모두 Three.js 기본 도형으로 직접 만든 테스트 모델입니다. (11단계에서 직접 준비한 GLB 모델로 교체 가능)

## 1. 폴더 구조

```
pokemon-hide-seek-3d/
├── index.html              화면 구조 (시작/대기실/게임 HUD/결과/모달)
├── style.css               UI 스타일 (PC·모바일 반응형)
├── game.js                 메인: Firebase 연결, 화면 흐름, 게임 루프, 조준·포획, 점검 작업
├── world.js                [추가] Three.js 3D 월드: 맵·캐릭터·사물 모델, 카메라, 효과
├── controls.js             [추가] 입력: 키보드/마우스(포인터 잠금), 가상 조이스틱, 터치 시점
├── firebase-config.js      ★ 직접 입력: Firebase 웹 설정값
├── shared/                 [추가] 게임 코드와 규칙 생성기가 함께 쓰는 모듈
│   ├── config.js           게임 설정(인원·시간·거리·쿨다운), 점수, 캐릭터/사물 목록
│   ├── forest-map.js       포켓몬 숲 맵 생성(결정적), 충돌, 시야 판정
│   └── actions.js          게임 동작 → DB 업데이트 묶음 (방 만들기, 참가, 포획, 변신, 전적…)
├── database.rules.json     ★ Firebase 에 게시: 보안 규칙 (게임 규칙 검사)
├── scripts/build-rules.mjs [추가] config.js 숫자로 database.rules.json 을 만드는 스크립트
├── firebase.json           Firebase CLI 설정 (규칙 배포 / 로컬 에뮬레이터, 선택)
├── .firebaserc             Firebase CLI 를 쓸 때만: 프로젝트 ID
├── tests/                  개발용 테스트 (배포와 무관)
│   ├── rules.test.mjs      보안 규칙 + 게임 동작 테스트 14개
│   ├── rules-sim.js        보안 규칙 시뮬레이터
│   └── browser/            브라우저 스모크 테스트 (Playwright, 선택)
├── package.json            테스트·규칙 생성 스크립트
├── .nojekyll               GitHub Pages 가 파일을 그대로 제공하도록
└── README.md
```

**권장 구조에서 추가한 파일과 이유**
- `world.js`, `controls.js`: 3D 모델링·입력·네트워크를 `game.js` 하나에 넣으면 너무 길어져 수정이 어렵습니다.
- `shared/actions.js`: 서버가 없으므로 모든 게임 동작을 "한 번에 기록하는 업데이트 묶음"으로 만듭니다. 게임과 테스트가 같은 코드를 씁니다.
- `scripts/build-rules.mjs`: 보안 규칙에 이동 속도·포획 거리·시간 같은 숫자가 들어가는데, 손으로 맞추면 실수하기 쉬워서 `shared/config.js` 에서 자동 생성합니다.

## 2. Spark 요금제에서 게임 규칙을 지키는 방법

서버 코드가 없기 때문에 역할이 이렇게 나뉩니다.

| 담당 | 하는 일 |
|---|---|
| **보안 규칙** (Firebase 서버에서 실행, 조작 불가) | 누가 무엇을 쓸 수 있는지 + 그 값이 게임 규칙에 맞는지 검사. 맞지 않으면 쓰기 전체 거부 |
| **각 참가자 브라우저** | 화면, 입력, 내 위치 전송, 조준, 포획·변신 요청 |
| **방장 브라우저** | 라운드 시작(술래 무작위 배정), 오래 끊긴 참가자 정리·기권 처리, 경기 기록 |
| **아무 참가자 브라우저** | 시간 종료/모두 포획 시 라운드 종료 기록, 방장이 사라지면 방장 이어받기, 내 전적 기록 |

**보안 규칙이 실제로 막는 것** (`tests/rules.test.mjs` 로 검증)
- 21번째 참가 (참가 자리 `s0`~`s19` 를 한 사람씩만 차지), 같은 방의 중복 닉네임, 게임 중 새 참가
- 역할(술래/숨는 팀)·생존 상태·제한 시간을 참가자가 스스로 바꾸기
- 방장이 아닌 사람의 게임 시작, 방장의 시작 시각 조작(서버 시각 ±3초만 허용)
- 순간이동·과속 이동(경과 시간 × 초당 9단위까지), 맵 밖 이동, **변신 중 이동**, **숨는 시간 동안 술래 이동**
- 숨는 팀이 아닌 사람의 변신, 허용되지 않은 사물, 해제 후 3초 안의 재변신
- **포획** — 아래 조건을 모두 만족해야만 기록됨
  - 요청자가 이번 라운드의 술래, 대상이 아직 살아 있는 숨는 팀 (일반 사물·술래·자기 자신 불가)
  - 숨는 시간이 끝났고 제한 시간 전 (서버 시각)
  - 포획과 동시에 기록한 **술래 위치**와 대상 위치의 거리 ≤ 3.35 (술래 위치 자체도 속도 규칙을 통과해야 함)
  - 직전 성공 포획 후 1.2초 경과 (쿨다운)
  - 이미 잡힌 대상은 다시 잡을 수 없음 → **두 술래가 동시에 잡아도 한 명만 성공**
- 생존자가 남았는데 술래 팀 승리 기록, 시간 전에 숨는 팀 승리 기록, 라운드 두 번 종료
- **전적 조작**: 전적은 본인만 쓸 수 있지만, 규칙이 방의 라운드 결과(승패, 포획 수, 생존 여부, 포획 시각)와 대조해 점수·승패·생존 시간이 정확히 맞을 때만 허용. 같은 라운드는 한 번만 기록됨
- 다른 사람의 전적 수정, 연결이 끊긴 지 45초가 안 된 사람의 기권 처리, 온라인인 방장 빼앗기

**규칙으로 막을 수 없는 것**은 10단계에 정직하게 적었습니다. (벽 너머 3m 이내 포획, 정보 엿보기, 방장 권한 등)

## 3. Firebase 프로젝트와 Realtime Database 설정

1. <https://console.firebase.google.com> → **프로젝트 추가** → 이름 입력 (애널리틱스는 꺼도 됩니다). 요금제는 **Spark(무료) 그대로** 둡니다.
2. **빌드 → Realtime Database → 데이터베이스 만들기**
   - 위치: **싱가포르(asia-southeast1)** 권장 (한국에서 가장 가까움)
   - 보안 규칙: **잠금 모드로 시작** (5단계에서 이 프로젝트의 규칙으로 바꿉니다)
3. **프로젝트 설정(톱니바퀴) → 일반 → 내 앱 → 웹(`</>`)** → 앱 닉네임 입력 → 등록 (Hosting 체크 불필요)
4. 표시되는 `firebaseConfig` 값을 **`firebase-config.js`** 에 그대로 옮깁니다.
   - `databaseURL` 이 없다면 Realtime Database 페이지 상단 주소(`https://…firebasedatabase.app`)를 복사해 넣으세요.

> `firebase-config.js` 의 값은 공개되어도 되는 식별 정보입니다. 보안은 로그인 + 보안 규칙이 담당합니다. 서비스 계정 키(JSON) 같은 비밀 값은 필요 없으며 절대 넣지 마세요.

## 4. Firebase Authentication 설정

1. **빌드 → Authentication → 시작하기**
2. **Sign-in method → 익명 → 사용 설정 → 저장**
3. **Settings → 승인된 도메인 → 도메인 추가**: `내아이디.github.io` (`localhost` 는 기본 포함)

플레이어는 처음 접속할 때 자동으로 익명 계정을 받고, 그 UID 가 전적의 주인입니다. 닉네임은 표시용일 뿐 식별에 쓰이지 않습니다.
같은 브라우저에서는 새로고침해도 같은 계정이지만, **브라우저 데이터를 지우거나 다른 기기에서 접속하면 새 사용자**가 됩니다.

## 5. 보안 규칙 배포 / 데이터 구조 / 포획 검증

### 배포 방법 (둘 중 하나)
**A. 콘솔에 붙여넣기 (가장 쉬움, 설치 불필요)**
1. Firebase 콘솔 → **Realtime Database → 규칙** 탭
2. 기존 내용을 모두 지우고 `database.rules.json` 파일 내용 전체를 붙여넣기
3. **게시**

**B. Firebase CLI**
```bash
npm install -g firebase-tools
firebase login
# .firebaserc 의 YOUR_FIREBASE_PROJECT_ID 를 내 프로젝트 ID 로 바꾼 뒤
firebase deploy --only database
```

규칙을 게시하지 않으면 방 만들기에서 "보안 규칙이 배포되었는지 확인해 주세요" 오류가 납니다.
`shared/config.js` 의 숫자(이동 속도, 포획 거리, 시간, 최대 인원, 캐릭터·사물 목록)를 바꿨다면 `node scripts/build-rules.mjs` 로 규칙을 다시 만들고 다시 게시하세요.

### 데이터 구조

| 경로 | 주요 필드 | 쓰기 권한 (규칙) |
|---|---|---|
| `rooms/{code}/meta` | `hostId, status(lobby/playing/results), mapId, roundNumber, maxPlayers, createdAt, seekerMode` | 생성자. 상태 변경은 방장(시작·대기실) / 참가자(종료 조건 충족 시) |
| `rooms/{code}/slots/{s0~s19}` | uid | 빈 자리만 본인이 차지 → 최대 20명 보장 |
| `rooms/{code}/nicks/{소문자닉네임}` | uid | 중복 닉네임 방지 |
| `rooms/{code}/players/{uid}` | `nickname, slot, character, ready, joinedAt, disguise, undisguisedAt` | 본인(참가·준비·캐릭터·변신), 방장(대기실에서 내보내기·초기화) |
| `rooms/{code}/round` | `id, number, phase, startedAt, hideEndsAt, roundEndsAt, seekers, hiders, alive(남은 숨는 팀), activeSeekers, names, captures, captureCount, left, winner, endedAt` | 시작은 방장, 이후 포획·종료·기권은 위 2단계 조건으로만 |
| `roomPos/{code}/{uid}` | `x, z, r(방향), t(서버 시각)` | 본인 (속도·경계·고정 규칙), 시작 위치는 방장 |
| `roomPresence/{code}/{uid}` | `online, at` | 본인. 연결이 끊기면 Firebase 서버가 `online:false` 로 바꿈 |
| `userRooms/{uid}` | 방 코드 | 본인 (재접속 안내용) |
| `playerStats/{uid}` | `nickname, gamesPlayed, wins, losses, captures, survivals, totalSurvivalSeconds, points, updatedAt, lastRound, lastRoom` | 본인, **라운드 결과와 일치할 때만** |
| `statRounds/{uid}/{roundId}` | true | 본인 (라운드당 한 번 기록 표시) |
| `matchHistory/{roundId}` | `roomId, startedAt, endedAt, winner, playerResults` | 그 방 참가자, 한 번만 |

자주 바뀌는 위치(`roomPos`)는 방 데이터와 분리해서 필요한 경로만 구독합니다. 읽기는 방 참가자만 가능하고, 방 코드를 아는 사람은 참가 전 확인용으로 `meta / slots / nicks` 만 읽을 수 있습니다.

### 포획이 기록되는 과정
1. 술래가 화면 중앙 조준점으로 대상을 맞춤 → 3m 이내이고 장애물이 없으면 조준점이 노랗게 변함 (실제 사물과 변신한 플레이어를 구별하지 않음)
2. 포획 버튼(PC: `F` 또는 좌클릭) → 브라우저가 거리·시야·일반 사물 여부를 먼저 확인 (빗나가면 1.5초 대기)
3. 브라우저가 `포획 기록 + 대상 생존 해제 + 내 포획 수 + 내 현재 위치` 를 **한 번에** 기록 요청 (`shared/actions.js → captureUpdate`)
4. Firebase 서버의 보안 규칙이 2단계의 포획 조건을 모두 검사 → 하나라도 어긋나면 **전체 거부**, 통과하면 모든 참가자 화면에 즉시 반영
5. 남은 숨는 팀이 0명이 되면 아무 참가자 브라우저가 라운드 종료를 기록 (규칙이 "생존자 0명"을 확인)

## 6. GitHub Pages 배포

1. GitHub 에 새 저장소를 만들고 이 폴더 전체를 올립니다.
2. 저장소 **Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: `main` / `(root)` → Save**
3. 1~2분 뒤 `https://내아이디.github.io/저장소이름/` 로 접속합니다.
4. 4단계의 **승인된 도메인**에 `내아이디.github.io` 가 있는지 확인하세요.

GitHub Pages 에 올리는 것은 정적 파일뿐이고, 따로 배포할 서버 기능은 없습니다. (보안 규칙만 5단계로 Firebase 에 게시)
수정 후 바로 반영되지 않으면 강력 새로고침(Ctrl+Shift+R) 하세요.

## 7. 로컬에서 테스트하기

### A. 실제 Firebase 에 연결해서 (가장 간단)
```bash
cd pokemon-hide-seek-3d
npx http-server -p 8080 -c-1 .      # 또는: python -m http.server 8080
```
`http://localhost:8080` 접속. (ES 모듈이라 파일을 더블클릭해서 열면 동작하지 않습니다.)

### B. Firebase 에뮬레이터로 (실제 DB 사용량 없이, 선택)
Java 11 이상과 Firebase CLI 가 필요합니다. 에뮬레이터는 무료이며 요금제와 무관합니다.
```bash
firebase emulators:start --project demo-hideseek
# 다른 터미널
npx http-server -p 8080 -c-1 .
```
`http://localhost:8080/?emulator` 로 접속하면 내 컴퓨터의 인증·DB 에뮬레이터에 연결됩니다. 에뮬레이터 UI(`http://localhost:4000`)에서 DB 내용과 규칙 거부 로그를 볼 수 있습니다.

### 한 컴퓨터에서 여러 명 테스트
같은 브라우저의 탭들은 같은 익명 계정을 공유합니다. 주소에 **`?newUser`** 를 붙이면 탭마다 새 사용자가 됩니다.
- 실제 Firebase: `http://localhost:8080/?newUser` / 에뮬레이터: `http://localhost:8080/?emulator&newUser`
- `?newUser` 탭은 새로고침하면 다른 사용자가 되므로 **재접속 테스트는 `?newUser` 없이** 하세요.

### 자동 테스트 (Node.js 20 이상, 설치 불필요)
```bash
npm test
```
`shared/actions.js` 가 만드는 실제 기록 묶음을 `database.rules.json` 에 통과시켜 봅니다: 20명 제한·21번째 거부, 중복 닉네임, 시작 권한, 역할 위조, 순간이동·변신 중 이동·숨는 시간 술래 이동, 변신 쿨다운, **접촉만으로는 포획 안 됨**, 숨는 시간·거리 밖·일반 사물·쿨다운·중복·숨는 팀의 포획 거부, 동시 포획, 조기 종료 거부, 전적 조작·중복 기록 거부, 기권·방장 위임, 방 정리, 다음 라운드.
(`tests/rules-sim.js` 는 Firebase 규칙 엔진을 흉내 낸 것이므로, 배포 전 B 의 에뮬레이터나 콘솔 **규칙 플레이그라운드**로 한 번 더 확인하면 가장 확실합니다.)

**디버그 옵션**: 주소에 `?debugCapture` 를 붙이면 브라우저의 사전 검사(거리·시야·일반 사물)를 건너뛰고 포획 요청을 그대로 보냅니다. 보안 규칙이 거리 밖·일반 사물 포획을 거부하는지 직접 확인할 때 쓰세요.

## 8. 조작 방법

**PC**
| 동작 | 키 |
|---|---|
| 이동 | `W A S D` 또는 방향키 |
| 시점 | 화면을 한 번 클릭하면 마우스 잠금 → 마우스로 회전 (`Esc` 해제). 잠그지 않고 드래그해도 회전 |
| 포획 (술래) | 조준점을 대상에 맞추고 `좌클릭`(잠금 중) 또는 `F`, 또는 화면의 **포획** 버튼 |
| 변신 / 해제 (숨는 팀) | `E` → 사물 선택 창에서 클릭 또는 `1`~`7` |
| 메뉴 | 왼쪽 위 ≡ 버튼 |

**모바일**
| 동작 | 방법 |
|---|---|
| 이동 | 화면 왼쪽을 누르고 드래그 (누른 곳에 조이스틱 생성) |
| 시점 | 화면 오른쪽을 드래그 |
| 포획 | 오른쪽 아래 **포획** 버튼 (포획 가능 거리에서 빨갛게 강조) |
| 변신 | **변신** 버튼 → 사물 선택 / 다시 누르면 해제 |

가로 화면을 권장합니다. 게임 중에는 확대·스크롤·더블탭 확대가 막혀 있습니다.

**규칙 요약**
- 숨는 시간 20초(+시작 3초) 동안 술래는 가림막 화면에서 움직일 수 없습니다.
- 변신 중에는 이동할 수 없습니다. 해제 후 3초 동안 다시 변신할 수 없습니다.
- 진짜 사물을 포획하면 "빗나감"이며 1.5초 대기합니다.
- 숨는 팀의 이름표는 술래에게 보이지 않습니다 (같은 팀끼리만 표시).
- 점수: 포획 1명당 10점 / 끝까지 생존 20점 / 승리 팀 10점. 중도 이탈은 패배·0점.
- 순위: 점수 → 승리 수 → 적은 플레이 수 → 닉네임 순.

## 10. 알려진 한계와 Spark 무료 사용량

### 서버 코드 없이 생기는 한계 (정직한 범위)
보안 규칙은 "기록하려는 값이 조건에 맞는가"만 검사할 수 있고, 반복 계산(맵 전체의 벽 검사)이나 무작위 생성은 할 수 없습니다. 그래서 아래는 **완전히 막지 못합니다.**
- **벽 너머 포획**: 시야(벽·나무·바위) 판정은 술래의 브라우저가 합니다. 조작된 브라우저는 **3.35m 이내라면** 벽 너머 대상을 잡을 수 있습니다. (거리·시간·역할·쿨다운은 규칙이 강제하므로 멀리서 잡거나 연속으로 잡는 것은 불가)
- **정보 엿보기**: 화면을 그리려면 모든 참가자가 방의 위치·역할·변신 정보를 읽어야 합니다. 개발자 도구로 DB 를 보면 어떤 사물이 플레이어인지 알 수 있습니다.
- **벽 통과 이동**: 규칙은 속도와 맵 경계만 검사합니다. 조작된 브라우저는 장애물을 통과할 수 있습니다(속도 제한은 지켜야 함).
- **방장 권한**: 술래 무작위 배정과 "모두 준비" 확인은 방장 브라우저가 합니다. 방장을 조작하면 원하는 사람을 술래로 정할 수 있습니다. 이벤트에서는 운영진이 방을 만들어 주세요.
- **전적 누락**: 전적은 각자 브라우저가 라운드 종료 직후 기록합니다(규칙이 결과와 대조). 종료 순간 브라우저를 닫은 사람이나 **중도 이탈자의 패배는 기록되지 않을 수 있습니다.** 방장은 결과 화면 3초 후부터 다음 라운드를 시작할 수 있습니다.
- **익명 계정**: 새 계정으로 다시 들어오는 것(부계정)은 막지 못합니다.
- **빈 방 정리**: 마지막 사람이 "나가기"를 누르면 방이 지워지지만, 모두 그냥 창을 닫으면 방 데이터가 남습니다. 12시간 지난 방은 누구나 지울 수 있게 해 두었고, 콘솔에서 `rooms` 를 직접 지워도 됩니다(방 하나 약 10KB).
- **처리 담당 브라우저**: 시간 종료·기권·방장 이어받기는 접속 중인 참가자의 브라우저가 처리하므로, 모두 백그라운드 탭이면 약간 늦어질 수 있습니다.

### 그 밖의 한계
- 개발 환경 제약으로 **실제 three.js 렌더링 화면, 실제 Firebase 서버의 규칙 엔진은 직접 확인하지 못했습니다.** 규칙 로직(시뮬레이터 14개 테스트)과 화면 흐름(브라우저 스모크 테스트)은 확인했으니, 게시 후 9단계 체크리스트와 콘솔 규칙 플레이그라운드로 꼭 확인해 주세요.
- 포획·변신은 DB 왕복이 필요해 100~300ms 정도 지연이 있습니다.

### Spark(무료) 요금제 사용량
| 항목 | Spark 한도 | 이 게임 |
|---|---|---|
| **동시 연결** | **100개** | 접속자 1명 = 연결 1개. 20명 방이면 동시에 약 5개 방까지 |
| **다운로드** | **월 10GB** | 가장 많이 쓰는 항목. 20명 방에서 10명이 계속 움직이면 라운드(3분)당 약 25~35MB → 월 약 300라운드 |
| 저장 용량 | 1GB | 방·전적·경기 기록, 매우 작음 |
| Authentication(익명) | 무료 | |
| GitHub Pages | 무료 | |

Spark 는 한도를 넘으면 **요금이 청구되지 않고 그 달 동안 서비스가 제한**됩니다. 사용량은 콘솔 Realtime Database → **사용량** 탭에서 확인하세요.
전송량을 더 줄이려면 `shared/config.js` 의 `POS_SEND_INTERVAL_MS` 를 150 → 200~250 으로 늘리세요(움직임 보간이 있어 크게 티 나지 않음). `matchHistory` 가 쌓이면 콘솔에서 지워도 됩니다.

## 11. 캐릭터·사물·맵 교체 방법

### 캐릭터 / 사물 3D 모델 (GLB)
직접 만들었거나 사용 허가를 받은 **GLB 모델**만 사용하세요. (공식 포켓몬 모델 무단 사용은 저작권 문제가 될 수 있습니다)
1. 저장소에 `assets/` 폴더를 만들고 `.glb` 파일을 넣습니다. 바닥 중심이 원점, 앞쪽이 +Z 방향이면 가장 잘 맞습니다.
2. `world.js` 위쪽의 `MODEL_OVERRIDES` 를 채웁니다.
   ```js
   export const MODEL_OVERRIDES = {
     characters: { volt: { url: './assets/volt.glb', scale: 0.9, y: 0, rotY: 0 } },
     props: { barrel: { url: './assets/barrel.glb', scale: 1 } },
   };
   ```
3. 사물을 바꿨다면 `shared/config.js` 의 `PROP_TYPES` 에서 그 사물의 `radius`(충돌·조준 반경), `height` 를 모델 크기에 맞춥니다.
- 맵에 놓인 사물과 변신한 플레이어는 **같은 모델**을 쓰므로 자동으로 똑같이 보입니다.
- 정적 모델만 지원합니다(애니메이션 없음). 불러오기에 실패하면 기본 테스트 모델이 쓰입니다.

### 캐릭터·사물 종류 추가
`shared/config.js` 의 `CHARACTERS` 또는 `PROP_TYPES` 에 추가 → 새 사물이면 `world.js` 의 `buildPropParts()` 에 모양 추가 → `node scripts/build-rules.mjs` → 규칙 다시 게시 (규칙이 허용 목록을 검사하므로).

### 사물 수량, 나무 수, 벽 배치
`shared/forest-map.js` 의 `FOREST_SETTINGS` (`propCounts`, `treeCount`, `walls`, `buildings`, `paths`, `seed`) 를 수정합니다. 모든 참가자가 같은 버전의 파일을 받아야 같은 맵이 되므로, 배포 후 모두 새로고침하게 하세요.

### 새 맵 추가
1. `shared/forest-map.js` 를 복사해 `shared/beach-map.js` 등을 만들고 설정을 바꿉니다.
2. `game.js` 와 `world.js` 에서 `getForestMap()` 대신 `meta.mapId` 에 따라 맵을 고르게 바꿉니다.
3. `scripts/build-rules.mjs` 의 `mapId` 검사를 새 맵 ID 도 허용하도록 바꾸고 규칙을 다시 게시합니다.

### 게임 설정 값
인원, 시간, 포획 거리, 쿨다운, 술래 수 표, 점수는 모두 `shared/config.js` 의 `GAME_CONFIG`, `SCORE_CONFIG` 에 있습니다. 바꾼 뒤 `npm test` → `node scripts/build-rules.mjs` → 규칙 게시 → GitHub 에 반영 순서로 진행하세요.
